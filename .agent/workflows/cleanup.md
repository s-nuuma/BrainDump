# 静的解析 ＆ 整理ワークフロー (cleanup.md)

このワークフローは、プロジェクト内のコード品質向上、リファクタリング、およびデッドコード（未使用のファイル、エクスポート、依存関係）の削除やゴミファイルのクリーンアップを自律的かつ自動で行うためのレシピです。

---

## 🛠 ワークフロー手順

エージェントは以下のステップに従い、不要なアセットを安全に整理してください。

### Step 1: 未使用コードの検出 (Knipの実行)
1. プロジェクト内のデッドコード、未使用エクスポート、未使用ファイルを検出する。
   - コマンド: `npm run knip` または `npx knip` (存在する場合)
2. `knip` の出力ログを解析し、以下の項目を安全に削除または修正する。
   - **Unused files (未使用ファイル)**: どのモジュールからもインポートされていない不要なファイルを削除する。
   - **Unused exports (未使用エクスポート)**: 外部から参照されていない関数や型定義の `export` キーワードを削除する。
   - **Unused dependencies (未使用依存関係)**: `package.json` に定義されているが使われていないライブラリを `npm uninstall` する。

### Step 2: 自動フォーマットと自動リント修復 (ESLint / Prettier)
1. ESLint による自動修復可能な問題（未使用変数、単純な構文違反）を一括でクリーンアップする。
   - コマンド: `npm run lint -- --fix` または `npx eslint . --fix`
2. コードのスタイルとインデントをプロジェクト規約に沿って自動整形する。
   - コマンド: `npx prettier --write .` (存在する場合)

### Step 3: ゴミファイルのスキャンと削除
1. ローカルでの動作検証やデバッグの過程で散乱した、以下のような不要なログやデバッグ用ファイルを自動スキャンして削除する。
   - `*.log` (TypeScript や npm のエラーログなど)
   - `debug-*.html` (curlやスクレイピング時のデバッグアセット)
   - `*-error.txt`
   - `tsconfig.tsbuildinfo`
2. 同期スクリプト `sync-template.mjs` を実行することでもゴミファイルの自動クリーンアップが可能です。
   - コマンド: `node ../scripts/sync-template.mjs` (プロジェクトルートから)

### Step 4: 動作検証（ビルドチェック ＆ テスト）
クリーンアップによってプロジェクトの動作が壊れていないかを厳格に検証します。
1. `npm run build` を実行し、デッドコード削除後にNext.jsビルドが正常に通るか確認する。
2. `npm run test` を実行し、既存の単体テストが正常にパスすることを確認する。
3. もしビルドやテストが失敗した場合は、誤って必要なファイルを消したか、`export` を削りすぎた可能性があるため、git 履歴から復元して修正する。

### Step 5: 整理内容のコミット ＆ プッシュ
1. クリーンアップブランチ（または直接 main）にて、整理内容をコミットする。
   - コマンド: `git add . && git commit -m "chore: code cleanup and dead code elimination" --no-verify`
2. リモートへプッシュする。
   - コマンド: `git push origin HEAD`
