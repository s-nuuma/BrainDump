# デプロイ自動化ワークフロー (deploy.md)

本ファイルは、開発者またはAIエージェントがコマンド `/deploy` を入力した際に発動する、連鎖型自動化マクロ（Workflow）を定義します。
手動でのデプロイ作業によるミスを防ぎ、品質チェックを通過した安全なコードのみがデプロイされる仕組みを提供します。

---

## 1. ワークフロー概要
- **トリガーコマンド**: `/deploy`
- **実行条件**: プロジェクトディレクトリのすべてのテストとリントチェックが完全に通過すること。
- **実行順序**:
  1. `npm run lint` の実行 (コードスタイルの検証)
  2. `npm run test` の実行 (Vitestによる単体/結合テストの検証)
  3. 上記の双方が成功した場合にのみ、`npm run build` を実行 (Next.jsのビルド確認)
  4. ビルドに成功した場合、`firebase deploy` (または事前設定された環境へのデプロイコマンド) を実行。

---

## 2. 実行パイプライン（チェーン定義）

AIエージェントは `/deploy` の呼び出しを検知した際、以下のステップを自律的に、かつ順次実行してください。いずれかのステップでエラー（ステータスコードが0以外）が発生した場合は、**即座に処理を中断し、ユーザーにエラー内容を報告**してください。

### ステップ 1: リントチェック (Lint Check)
- **コマンド**: `npm run lint`
- **目的**: 静的解析を行い、型エラーや定義違反、コード規約違反がないことを検証する。

### ステップ 2: ユニットテストの実行 (Run Unit Tests)
- **コマンド**: `npm run test`
- **目的**: 変更によって既存機能のデグレードが発生していないか、および新規テストケースがすべてPassしているかを確認する。

### ステップ 3: 本番ビルドの作成 (Build Production Bundle)
- **コマンド**: `npm run build`
- **目的**: Next.js (App Router) がエラーなくHTML/JSの静的生成・コンパイルができることを保証する。

### ステップ 4: デプロイの実行 (Deploy to Firebase)
- **コマンド**: `firebase deploy`
- **目的**: すべての品質ゲートウェイを通過したビルドを、Firebase Hosting/Cloud Functions 等の本番/ステージング環境にデプロイする。
- **注意**: 初回デプロイ時にはあらかじめ `firebase login` および `firebase init` が完了している必要があります。
