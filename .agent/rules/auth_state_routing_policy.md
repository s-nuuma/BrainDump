# 認証状態ルーティング ＆ 画面遷移制御ルール (auth_state_routing_policy.md)

このルールは、認証状態の監視、ログイン/サインアップフロー、または Next.js の `middleware.ts` などのルーティング保護機能を実装・修正する意思決定（Model Decisionモード）を行う際に適用されます。

---

## 1. Middleware によるサーバーサイド認証ガード

未認証ユーザーがダッシュボードやマイページなどの保護領域にアクセスするのを防ぐためのセキュリティ設計です。

- **サーバーサイドでの防衛**:
  - 認証が必要なルートへのリクエストは、Next.js の `middleware.ts` を用いて、サーバーサイドでユーザーセッション（クッキーに保存されたセッションIDやFirebaseのIDトークン）の有無を検証してください。
  - セッションが未検出の場合は、ログインページ（`/login`）へ即座にリダイレクトさせ、HTMLなどの画面アセット自体を送信しない設計を適用します。

---

## 2. クライアントサイドにおける「チラつき (Flash)」防止設計

Firebase Auth の初期化（`onAuthStateChanged` の解決）には若干の時間差（数ミリ秒〜数百ミリ秒）があるため、適切なロード制御を挟みます。

- **初期化完了状態の管理**:
  - アプリ全体または認証が必要な領域は、`useAuth` などのカスタムフックや Context を用い、認証の初期化ステータス（例: `loading: boolean`）を提供してください。
  - 認証状態の判定が「未確定」の間（`loading` が `true` の間）は、認証済み用のコンテンツ（ダッシュボード等）や未認証用のコンテンツ（ログインフォーム）を中途半端にレンダリングせず、統一された**ローディングインジケータ（SpinnerやSkeleton UI）**を表示して、画面の不自然なチラつきを排除してください。

```typescript
// ⭕ 良い実装例 (Good)
const { user, loading } = useAuth();

if (loading) {
  return <LoadingSpinner />; // 認証状態が確定するまでチラつきを防ぐ
}

if (!user) {
  return <RedirectToLogin />;
}

return <DashboardContent user={user} />;
```

## 3. リダイレクト元の URL 追跡ハンドリング

ユーザーの操作体験（UX）を高めるため、認証後のスムーズな復帰導線を設計してください。

- **`redirectTo` クエリパラメータの付与**:
  - 未認証ユーザーが特定のURL（例: `/recipes/edit/123`）へ直接アクセスしてログイン画面にリダイレクトされた場合、その元のURLをクエリパラメータとして引き継がせてください。
  - 例: `/login?redirectTo=%2Frecipes%2Fedit%2F123`
- **ログイン成功後の遷移**:
  - ログイン処理が成功した際は、クエリパラメータ `redirectTo` の有無を確認し、存在すればそのパスへ自動遷移させ、なければデフォルトのダッシュボード（`/` 等）へ遷移させてください。
