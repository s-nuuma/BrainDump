# 初期プロジェクトセットアップ・タスクスキル

本スキルは、新しい機能領域やコンポーネントをプロジェクト内に新設する際の、初期化プロセスを定義したものです。

---

## 1. 段階的情報開示 (Progressive Disclosure) について
本ファイルは、プロジェクト開始時や初期化コマンドの実行時など、コンテキストが極端に必要とされるフェーズでのみエージェントのコンテキストキャッシュにロードされます。
通常の実装フェーズやテストコード記述フェーズにおいては、本ファイルを読み込まず、コンテキストトークンの消費を節約してください。

---

## 2. 実行手順とテンプレート展開

新規にコンポーネントやモジュールを追加する際は、以下の構成を作成します。

### ① `src/` 配下の基本コンポーネント構成
`src/` 内に新しい機能フォルダ（例: `src/features/search`）を作成する場合、以下の3つのファイルを基本セットとして生成します。

- `index.ts`: モジュール外部へ提供するインターフェースをエクスポートするエントリポイント。
- `types.ts`: その機能専用の TypeScript インターフェース定義。
- `components/`: UIコンポーネントの配置フォルダ。

### ② 仕様ファイル (`spec.md`) の初期化
新規機能を追加する場合は、`docs/spec.md` を作成または追記し、以下のフォーマットで要件を定義します。

```markdown
# [機能名] の仕様書

## 概要
機能の目的と期待される効果。

## 満たすべき要件
- [ ] 要件 1
- [ ] 要件 2

## UI/UX 設計
- 画面レイアウトの構成案
- 期待されるインタラクション
```
